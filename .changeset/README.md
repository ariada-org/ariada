# Changesets

Hello and welcome! This folder has been automatically generated by `@changesets/cli`, a build tool that works with multi-package repos, or single-package repos to help you version and publish your code. You can find the full documentation for it [in our repository](https://github.com/changesets/changesets).

We have a quick list of common questions to get you started engaging with this project in [our documentation](https://github.com/changesets/changesets/blob/main/docs/common-questions.md).

## ariada monorepo specifics

- **baseBranch:** `main` — changeset diffs against this branch to detect which packages changed.
- **access:** `public` — every published package goes to npm under the `@ariada` scope as a public package.
- **updateInternalDependencies:** `patch` — when package A bumps and package B depends on A via `workspace:*`, B gets a patch bump in the same release.
- **ignore list:** `@ariada-org/eaa-pipeline-meta` (private — composite Action ships via GitHub Marketplace + YAML reference), `@ariada-org/config` (private — internal shared config).

## Day-to-day workflow

When you make a code change that should ship to npm in the next release:

```bash
pnpm changeset            # interactive — pick package(s) and bump type (patch/minor/major) + write a short rationale
git add .changeset/<id>.md
git commit -m "feat(<pkg>): <subject>"
```

The changeset file is then carried forward in PRs. At release time:

```bash
pnpm changeset version    # consume all .changeset/*.md files, bump versions, regenerate CHANGELOG.md, update workspace deps
git add . && git commit -m "chore(release): version packages"
pnpm release              # alias for `pnpm changeset publish` — publishes in topological order with workspace:* rewrites
```

Per the monorepo replay strategy (see `scripts/replay-public-oss-repo.sh`), the initial public push of v0.1.0-rc.1 is done WITHOUT changesets (the 20-commit replay scaffold ships the initial CHANGELOG.md by hand). Changesets governs every release AFTER that.
