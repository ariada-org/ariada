# S159: Asana app

Asana apps can place external data and actions within projects and tasks where campaign, design, and web teams coordinate approvals; a planned Asana app would carry Ariada findings into the task that owns publication.

## Boundary

The app would not gain access beyond authorized Asana projects, infer product state from task status, or mark accessibility work complete automatically. It would not claim an Asana App Directory listing.

## Roles

- Web production coordinator
- Asana workflow designer

## Use cases

- Before a campaign page task receives approval, the coordinator would attach Ariada evidence and assign concrete corrections to design, copy, or engineering subtasks.
- The workflow designer would map resolved and recurring findings into existing Asana custom fields without creating a parallel status system that obscures accountability.

## Installation

Not installable: Asana app has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
