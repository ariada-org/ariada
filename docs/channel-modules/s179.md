# S179: Sentry integration

Sentry groups runtime events into issues and ties them to releases, environments, users, traces, and ownership rules; a proposed Sentry integration would route selected Ariada regressions into the operational issue stream.

## Boundary

The integration would not treat automated accessibility findings as runtime exceptions, collect end-user data unnecessarily, or close issues based solely on a later scan. It would use scoped ingestion and would not imply current Sentry availability.

## Roles

- Sentry issue owner
- Frontend reliability engineer

## Use cases

- A confirmed release regression would create or update a Sentry issue keyed by rule, route, and element signature, with environment metadata needed for reproduction.
- The reliability engineer would compare Ariada evidence across Sentry releases and assign the issue through existing code ownership without labeling it as a JavaScript crash.

## Installation

Not installable: Sentry integration has no qualifying public implementation or package in the canonical Ariada repository.
