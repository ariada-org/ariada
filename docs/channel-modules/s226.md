# S226: Adobe Experience Manager (AEM) integration

Adobe Experience Manager authors assemble pages from components, templates, assets, and content fragments before activating them from author to publish environments; a planned AEM integration would supply Ariada evidence at that publication boundary.

## Boundary

The integration would not activate pages, modify repository content, approve workflows, or certify every component and dynamic personalization. It would require explicit author or preview access and would not imply an Adobe Exchange offering.

## Roles

- AEM publication manager
- Experience-fragment component lead

## Use cases

- Before activation, the publication manager would review an AEM page in preview with representative content fragments, assets, navigation, and form states.
- After a core component policy changes, the component lead would sample affected templates and locales, then fix shared implementation defects instead of editing each page.

## Installation

Not installable: Adobe Experience Manager (AEM) integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
