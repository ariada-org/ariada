# S43: Turbopack/Next loader integration

A planned Turbopack-aware Next.js integration would be a versioned package configured through APIs the framework actually supports, giving App Router teams a way to scan rendered development or preview routes rather than treating bundled modules as pages.

## Boundary

No loader or Turbopack integration exists, and compatibility with Webpack loaders must not be assumed; a future design would depend on documented Next.js and Turbopack extension points and could inspect only routes and states supplied to it.

## Roles

- Next.js App Router platform engineer
- Turbopack migration release owner

## Use cases

- A platform engineer would start a preview build, render representative static and server routes with fixtures, and associate findings with that build.
- A migration owner would test the integration against a specific Next.js release and confirm it does not rely on Webpack-only loader behavior before rollout.

## Installation

Not installable: Turbopack/Next loader integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned

- No qualifying public implementation evidence is declared and present on the canonical public tree.
