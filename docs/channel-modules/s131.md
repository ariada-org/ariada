# S131: Selenium integration

Selenium drives real browser sessions through WebDriver, often across Grid nodes and language-specific test suites; a proposed Selenium integration would return Ariada findings for the pages automation engineers deliberately expose during a session.

## Boundary

Ariada would not replace WebDriver commands, Selenium Grid, functional assertions, or human accessibility evaluation. The integration would be limited to reachable browser DOM states and would remain a design rather than an implemented connector.

## Roles

- Selenium automation engineer
- Grid capacity coordinator

## Use cases

- After Selenium switches into an application frame, the automation engineer would review that frame's rendered controls instead of assuming a top-level page scan includes them.
- The grid coordinator would correlate Ariada evidence with browser, operating-system, and session identifiers before escalating a finding seen on one capability set.

## Installation

Not installable: Selenium integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned

- No qualifying public implementation evidence is declared and present on the canonical public tree.
