# S16: pre-commit / git-hook integration

The planned integration would be a versioned pre-commit hook repository and hook definition that repository owners add to `.pre-commit-config.yaml`, giving contributors a local scan of selected staged web files before a commit is created.

## Boundary

No hook repository or executable entry is available; a future hook would inspect only configured files, leave staging and commit decisions to Git, avoid changing content by default, and never substitute for rendered-page testing.

## Roles

- Repository pre-commit policy administrator
- Web contributor preparing a commit

## Use cases

- A contributor would run the Ariada hook against staged templates, correct a reported issue, and restage the file before committing.
- A repository administrator would pin a hook revision, define file filters, and test behavior for skipped, failed, and partially staged files before team rollout.

## Installation

Not installable: pre-commit / git-hook integration has no qualifying public implementation or package in the canonical Ariada repository.
