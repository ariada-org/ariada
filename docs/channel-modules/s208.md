# S208: Klaviyo landing/email scan recipe

Klaviyo marketers publish one-time campaigns and automated flows from templates populated with profile and catalog data, alongside forms and hosted pages; a proposed scan recipe would support pre-send accessibility review of each rendered variant.

## Boundary

The recipe would not read customer profiles, trigger live flows, send messages, or modify Klaviyo templates. Dynamic personalization and inbox rendering would require safe test data and human checks; no app implementation is claimed.

## Roles

- Klaviyo lifecycle marketer
- Email personalization QA analyst

## Use cases

- Before activating a Klaviyo flow message, the QA analyst would send test variants with missing and long catalog fields and review the resulting email HTML.
- The lifecycle marketer would separately evaluate a Klaviyo signup form and hosted preference page for labels, errors, focus, and consent language.

## Installation

Not installable: Klaviyo landing/email scan recipe has no qualifying public implementation or package in the canonical Ariada repository.
