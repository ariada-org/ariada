# S189: Ionic integration

Ionic applications compose mobile-oriented web components into browser, PWA, or hybrid WebView experiences; a proposed Ionic integration would review the rendered web layer used by hybrid-app engineers and mobile QA teams.

## Boundary

The integration would not infer native shell, device permission, or assistive-technology behavior from browser DOM alone. It would leave Ionic source unchanged, require device testing for packaged apps, and remain unimplemented.

## Roles

- Ionic UI engineer
- Hybrid mobile QA analyst

## Use cases

- The UI engineer would render Ionic menus, modals, inputs, and validation states in a browser test harness and review Ariada evidence before packaging.
- The mobile QA analyst would reproduce high-impact findings inside the actual iOS and Android WebViews, including screen-reader and virtual-keyboard behavior.

## Installation

Not installable: Ionic integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
