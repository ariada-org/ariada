# S217: Moodle plugin

Moodle plugins extend course activities, blocks, editors, reports, and administration through its plugin directory, while learners use themed course and activity pages; a planned Moodle plugin would support accessibility evidence in course publishing workflows.

## Boundary

The plugin would not grade learners, alter course content, change roles, or certify Moodle themes and third-party activities. It would review explicitly rendered pages and would not imply plugin-directory publication.

## Roles

- Moodle course designer
- Learning-platform administrator

## Use cases

- Before opening a Moodle course, the designer would review the course index, lesson resources, quiz instructions, feedback, and completion states using a learner account.
- The administrator would test a theme or activity-plugin update across representative courses and route shared defects to platform code rather than individual instructors.

## Installation

Not installable: Moodle plugin has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
