# S6: CI adapters for non-GitHub CI (new builds)

The proposed adapters would be reusable pipeline jobs or command wrappers for systems such as CircleCI, Buildkite, and TeamCity, giving CI authors a platform-native way to pass built web artifacts to Ariada and retain reports with a run.

## Boundary

No non-GitHub adapter is implemented; each future adapter would invoke analysis on declared inputs while the host CI system continues to own runners, secrets, artifact retention, status rules, and release approval.

## Roles

- Cross-platform CI configuration engineer
- Release evidence governance lead

## Use cases

- A Buildkite pipeline author would add a post-build step that scans the generated site and uploads the report beside the build artifacts.
- A TeamCity administrator would evaluate runner prerequisites and map Ariada's exit status into an existing quality gate without granting the adapter deployment authority.

## Installation

Not installable: CI adapters for non-GitHub CI (new builds) has no qualifying public implementation or package in the canonical Ariada repository.
