# S165: n8n node

n8n nodes supply typed operations inside self-hosted or cloud workflows, with credentials and execution data controlled by the workflow owner; a planned n8n node would request and retrieve Ariada review results for explicit targets.

## Boundary

The node would not inherit permission to crawl internal networks, store credentials in workflow output, or make an execution result a certification. No community or verified node package would be implied by this plan.

## Roles

- n8n workflow engineer
- Self-hosted automation operator

## Use cases

- After a deployment webhook reaches n8n, the workflow engineer would submit the preview URL and wait for a stable Ariada review result before routing owned defects.
- The operator would redact secrets from execution logs and constrain any planned node to approved hosts when reviewing applications inside a private environment.

## Installation

Not installable: n8n node has no qualifying public implementation or package in the canonical Ariada repository.
