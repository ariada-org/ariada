# S121: UXPin integration

A future UXPin integration would surface Ariada review evidence for interactive prototypes and design-system components, including code-backed Merge components, where designers and system owners evaluate realistic states before implementation review.

## Boundary

The integration would report on submitted previews and component states, not rewrite UXPin documents or source components. It would not prove production behavior, exercise every prototype transition automatically, or imply a shipping module.

## Roles

- Design-system product owner
- Prototype accessibility reviewer

## Use cases

- When a UXPin library component gains an error state, the system owner would review the rendered state for naming, contrast, and focus treatment before releasing the library update.
- A prototype reviewer would follow a checkout flow in UXPin Preview, attach Ariada evidence to the relevant screen, and request missing keyboard behavior before stakeholder sign-off.

## Installation

Not installable: UXPin integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
