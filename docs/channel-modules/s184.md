# S184: PagerDuty integration

PagerDuty receives events for services, deduplicates them into incidents, and applies escalation policies and on-call schedules; a planned PagerDuty integration would alert on explicitly defined Ariada release regressions.

## Boundary

Not every accessibility finding is an operational incident, so the integration would require governed urgency thresholds and deduplication. It would not alter schedules, auto-resolve accepted risk, or imply a PagerDuty Marketplace listing.

## Roles

- PagerDuty service owner
- Accessibility incident commander

## Use cases

- A production deployment that introduces a predefined blocking regression would trigger one deduplicated PagerDuty incident linked to the Ariada evidence and owning service.
- The incident commander would resolve the operational alert only after mitigation is verified, while preserving the underlying finding's separate remediation history.

## Installation

Not installable: PagerDuty integration has no qualifying public implementation or package in the canonical Ariada repository.
