# S175: Fly.io integration

Fly.io deploys applications as releases running on Machines across regions, with app domains, logs, and health checks; a planned Fly.io integration would target a selected HTTP app and preserve region and release context.

## Boundary

Ariada would not manage Machines, secrets, scaling, certificates, or regions, and one regional web review would not prove global behavior. The connection would require an exposed target and would not imply delivered Fly tooling.

## Roles

- Fly.io application operator
- Regional release observer

## Use cases

- The release observer would review a canary Fly.io deployment through its assigned hostname and correlate evidence with the release before shifting traffic.
- For region-dependent content, the operator would supply the intended route and locale, then separate edge or health-check failures from page accessibility findings.

## Installation

Not installable: Fly.io integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence
