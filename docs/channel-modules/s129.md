# S129: WebdriverIO service

WebdriverIO services hook into runner sessions, commands, and reports across local browsers or remote grids; a future WebdriverIO service would let automation owners collect Ariada evidence at selected points in a test suite.

## Boundary

The service would not confer accessibility coverage on every WebdriverIO spec or control a remote provider. It would observe configured page states only, avoid automatic remediation, and make no claim that a distributable service exists.

## Roles

- WebdriverIO suite architect
- Remote-grid operations analyst

## Use cases

- After a WebdriverIO test opens a navigation drawer, the suite architect would capture Ariada findings for that transient state and attach them to the session report.
- When remote-grid runs disagree, the operations analyst would use browser and capability metadata to separate an accessibility regression from an environment failure.

## Installation

Not installable: WebdriverIO service has no qualifying public implementation or package in the canonical Ariada repository.
