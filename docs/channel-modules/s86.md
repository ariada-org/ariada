# S86: Alfred workflow

A future Alfred workflow would be a signed `.alfredworkflow` bundle or Gallery-listed workflow that lets macOS automation users launch Ariada for an entered URL or selected local file.

## Boundary

No Alfred bundle or Gallery entry exists; a future workflow would wrap only a declared local executable or service, would not inspect arbitrary desktop applications, capture browser state, modify files, or imply accessibility approval.

## Roles

- Alfred automation workflow user
- Desktop accessibility consulting analyst

## Use cases

- An analyst would type a workflow keyword, submit a staging URL, and open the generated report from Alfred's result list.
- A workflow publisher would test dependencies, environment paths, configuration fields, update behavior, signing, and Gallery metadata before distribution.

## Installation

Not installable: Alfred workflow has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
