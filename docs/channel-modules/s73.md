# S73: pre-commit.ci

A future pre-commit.ci setup would connect a public hook definition with the hosted service that runs configured hooks on pull requests and proposes automated hook-revision updates for repository teams.

## Boundary

No Ariada hook or pre-commit.ci configuration is available; the hosted service would execute only the repository's declared hook, while repository owners control installation, file filters, autofix policy, merge requirements, and target authorization.

## Roles

- Pull-request hygiene policy owner
- pre-commit.ci repository administrator

## Use cases

- A repository administrator would enable pre-commit.ci and confirm that the Ariada hook reports on changed supported files without committing unapproved edits.
- A contributor would inspect the hook output on a pull request and resolve a finding before the required CI check is rerun.

## Installation

Not installable: pre-commit.ci has no qualifying public implementation or package in the canonical Ariada repository.
