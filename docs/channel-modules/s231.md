# S231: Bazel rule

Bazel rules declare inputs, tools, actions, and outputs for reproducible targets in a dependency graph; a planned Bazel rule would produce Ariada review artifacts for a built and served web target under explicit test conditions.

## Boundary

Network-dependent page review does not automatically satisfy Bazel hermeticity, so the rule would need a documented execution model. It would not alter source, deploy outputs, or imply an available rule set or remote-execution support.

## Roles

- Bazel rule author
- Hermetic-build systems reviewer

## Use cases

- A rule author would declare the built site, review configuration, and controlled server as inputs, then emit a structured Ariada artifact rather than an undeclared network side effect.
- The systems reviewer would decide whether execution belongs in a local test, sandboxed CI job, or non-hermetic pipeline before enabling remote caching.
