# S234: Lit dev integration

Lit developers build standards-based web components and review them through local demo pages, web test runners, or documentation sites; a proposed Lit dev integration would run Ariada against those explicit rendered fixtures.

## Boundary

The integration would not infer accessibility from a Lit class or template source without rendering, and it would not cover every consumer context. It would not modify components or imply an available development package.

## Roles

- Lit component author
- Shadow-DOM test specialist

## Use cases

- A component author would render each public state and slot combination on a Lit demo page, then review Ariada evidence before releasing a version.
- The test specialist would inspect focus delegation, accessible naming, and relationships across shadow boundaries while documenting checks that still require manual evaluation.

## Installation

Not installable: Lit dev integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
