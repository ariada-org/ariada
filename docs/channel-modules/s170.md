# S170: Azure Static Web Apps integration

Azure Static Web Apps creates production and preview environments from repository branches and pull requests, often with managed routing and APIs; a proposed integration would attach Ariada evidence to the exact environment under release review.

## Boundary

Ariada would not configure Azure resources, approve a pull request, bypass preview authentication, or inspect API behavior that lacks a rendered interface. The integration would remain planned and separate from Azure deployment status.

## Roles

- Static Web Apps owner
- Azure pull-request reviewer

## Use cases

- The pull-request reviewer would examine changed routes on an Azure Static Web Apps preview and link Ariada regressions back to the originating change.
- Before swapping production content, the app owner would compare the preview environment's authenticated and public states while keeping deployment and accessibility decisions separate.

## Installation

Not installable: Azure Static Web Apps integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
