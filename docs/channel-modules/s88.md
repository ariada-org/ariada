# S88: tox / nox integration

The proposed tox and nox integration would be reusable environment configuration or documented sessions that install Ariada, start a test site when needed, and collect accessibility evidence across Python release environments.

## Boundary

No tox plugin, nox session package, or official recipe is delivered; these runners would orchestrate declared commands rather than add scanning capability, and projects would retain control of environments, services, fixtures, and pass criteria.

## Roles

- Python multi-environment release engineer
- Nox session workflow designer

## Use cases

- A nox session would build documentation, serve it on a test port, run Ariada against selected routes, and archive the report.
- A tox configuration owner would test dependency isolation, environment factors, command allow-listing, and cross-version behavior before sharing the recipe.

## Installation

Not installable: tox / nox integration has no qualifying public implementation or package in the canonical Ariada repository.

## Evidence

- State: Planned
- Updated from evidence: Not available
- No qualifying public implementation evidence is declared and present on the canonical public tree.
