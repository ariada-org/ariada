# ADR-0005: REUSE 3.3 compliance — per-file SPDX headers

## Status

Accepted

## Date

2026-04-15

## Context

In a monorepo with 23 packages, multiple licenses (EUPL-1.2 for code, CC0-1.0 for test fixtures, MIT for brand tokens, CC-BY-4.0 for some documentation), and hundreds of source files, tracking which license applies to which file is a real audit burden. EU Directive (EU) 2016/2102 (Web Accessibility Directive) and the Cyber Resilience Act (CRA, Regulation (EU) 2024/2847) both introduce SBOM and provenance requirements that downstream consumers will need to satisfy.

Two approaches were considered:

**Repository-wide LICENSE file only:** one `LICENSE` file at root, no per-file headers. Easier to maintain, but ambiguous when different packages ship different licenses. SBOM generators that crawl the repo cannot reliably infer the license for each file — they must make heuristic guesses. Fails REUSE specification.

**REUSE 3.3 per-file SPDX headers:** every source file carries a machine-readable `SPDX-FileCopyrightText:` and `SPDX-License-Identifier:` comment. The `REUSE.toml` file handles bulk declarations for generated files, lock files, and binary assets that cannot carry inline comments. The `reuse lint` tool validates compliance on every push.

## Decision

All files in the repository use REUSE 3.3 (https://reuse.software/spec-3.3.0/) for license and copyright tracking:

- Every source file carries `// SPDX-FileCopyrightText:` and `// SPDX-License-Identifier:` comments at the top (or `<!-- ... -->` for HTML/Markdown, `# ...` for shell/properties files).
- `REUSE.toml` declares bulk copyright and license for generated files, lock files, and binary assets.
- All license texts referenced in SPDX identifiers are present in the `LICENSES/` directory.
- `reuse lint` runs in CI (`ci.yml`) and must exit 0 before any commit is considered passing.
- SPDX SBOM is generated by `sbom.yml` workflow and attached to each release as `sbom.spdx.json` and `sbom.cdx.json` (CycloneDX format).

## Consequences

- **Positive:** unambiguous per-file license attribution; machine-readable SBOM generation; CRA-readiness; REUSE badge on README; NLnet evaluators can audit license compliance in seconds.
- **Negative:** new files require two additional comment lines; contributors unfamiliar with REUSE need education. The `reuse annotate` CLI command helps (`reuse annotate --copyright "2026 Agonist Development AB" --license EUPL-1.2 <file>`).
- **Neutral:** the `REUSE.toml` file currently handles ~30 generated/binary files that cannot carry inline comments — maintained alongside new file additions.

## Alternatives considered

- SPDX file-level tracking without REUSE tooling: possible but no automated lint gate.
- Per-package LICENSE files only: sufficient for npm consumers but insufficient for CRA SBOM requirements.
- No per-file headers (just root LICENSE): fails REUSE, makes SBOM generation heuristic, and is ambiguous for mixed-license packages.
